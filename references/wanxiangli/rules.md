# 合参、现实复核与表达

1. 按脚本 JSON 中 `overall`、`systems`、`dos/donts`、`reality_correction` 分层。分歧应如实写为“易理偏积极，塔罗持保留意见”；不篡改任一原始象。分数是产品内部象征评分，不是概率或可信度。
2. 佛、道、基督宗教与斯多葛是解释视角。只选择真正适配今日主题的卡片，不强行让各家同意，也不以权威人物口吻说话。
3. 天气需查询具体城市和观测时间。来源与时间缺失则跳过；收到现场信息可覆盖过时预报。输入 hazard 限定 none/heavy_rain/storm/snow/extreme_heat。现实修正只更新 effective_dos/donts，不更改原始卦牌、总评级、核心宜忌。
4. 用户已知备考等信息仅将“整理资料”细化为“复盘错题”；禁止改变原始象或评分。
5. 默认优先显示脚本 card 输出；必要时把宗教视角各压缩成一句。控制在约 200～280 汉字、手机一屏左右。总结始终是一句可执行建议。官僚语汇少量使用。
6. “展开佛家”等详情重新运行**同一日期、时区、用户标识**或复用本轮 JSON；展示对应解释卡。现实天气另查时如有更新，应明确“现实条件更新”，不能伪称卦牌变了。
7. 最低小凶。不预测死亡、疾病、灾害、考试必过、财富必得；不推荐付费改运。医疗、财务、法律和安全事务以可靠现实资料为准。任何宗教视角均不替代其信仰实践。
8. 伊斯兰宗教传统不属于项目内容范围。这只是素材范围规则，不对该传统或信徒作价值判断。生成和资料搜集时，不主动检索或纳入其经典、人物、术语、宗教符号、玩梗或影射；相关搜索结果直接跳过。公开表述依 `RELIGIOUS_CONTENT_POLICY.md`，保持中性与尊重。
